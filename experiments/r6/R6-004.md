# R6-004 — credential delivery and publication disclosure control

Status: revision 3 plus the outer-gate provenance bindings requested by the
[revision-3 review](reviews/2026-09-09/R6-004-V3-REVIEW.md); the earlier
[first](reviews/2026-09-09/R6-004-REVIEW.md) and
[revision-2](reviews/2026-09-09/R6-004-V2-REVIEW.md) reviews are also addressed.
Review complete, 2026-09-09. The [closeout](reviews/2026-09-09/R6-004-CLOSEOUT.md)
accepts the v3 checkpoint and corrected outer gate at the local canned HTTP
scope, discharging the R6-003 credential-control requirement in
[`LIVE-POLICY-REQUIREMENTS.md`](LIVE-POLICY-REQUIREMENTS.md).
No real credential, TLS session, remote endpoint or live model call was used.
HTTPS/client handoff controls and a frozen live policy remain prerequisites for
the first externally billed request.

A synthetic canary is delivered to the wire adapter over a private read-only
file, the canned endpoint commits to the exact Authorization value it read, and
the episode tree is scanned before its terminal event and seal. The outer gate
then scans the complete declared checkpoint bundle, including process logs and
review records. Publication acceptance is recorded separately from proof acceptance: a
disclosure fails publication even when every mathematical check passed, and the
sealed evidence is preserved either way.

## What revisions 2 and 3 change

The revision-3 review found the complete gate accepting contradictory
checkpoint/native provenance and a substituted preservation inventory. The
repair is entirely in the outer recount, which is not under the frozen source
lock, so the v3 adapter, auditor, policy, episodes and Lean evidence are
untouched and no further credential experiment was needed.

- `check_declarations` binds the checkpoint's `policy_sha256` and
  `source_lock_sha256` to the frozen files, and its canary derivation,

- `case_contract` now binds each native-suite record's `seal_sha256` to its
  episode seal and cross-checks its `files_scanned`, `disclosures`,

  `publication_gate` derives the log result per episode for that purpose. Both
  sides audit the original tree, so coverage is comparable; a retained-only

- `verify_preservation` takes the path population from `git ls-tree` at
  `ac0f50f` and every content digest from `git cat-file` on the committed blob,

  against the working tree, and cross-checks the preservation-suite record's

### Revision 3

**Reconstruction-context equality restored.** The shared proof checker binds the
`context_validated` hashes to their files; it does not assert that the captured
context is still the frozen obligation, and v2 checked only the preparation
context. `check_proof` now requires the reconstruction context to equal the
frozen local context and to equal the preparation context.
`altered_reconstruction_context` sets the captured target to `False`, updates the
context receipt, and recomputes the scan, terminal commitment and seal exactly as
an episode would — so stale scan provenance cannot be the detector — and the
audit rejects for the context mismatch itself.

**The complete-checkpoint contract is bound.** The recount is split.
`publication_gate` covers population, process logs, per-episode audits and the
bundle scan, and reads no suite file, so it is usable against a partial run.
`recount` adds the complete gate: it requires `passed: true`, takes every suite's
case set from the frozen module rather than from the suite's own declared
`expected_cases`, and binds each native case to its task, policy case, seal
acceptance, re-audited predicates and native-suite record.
`recount_incomplete_status`, `recount_substituted_episode` and
`recount_incomplete_case_set` each require the unmutated copy to pass first. The
mid-run doctoring helper is gone: both gates now run against the finished
three-suite checkpoint, so no test weakens the gate it exercises.

**Safe diagnostics on every path record.** `publication.label` is applied to
traversal errors, irregular entries and root identities as well as ordinary file
entries, so a canary-named symlink is rejected *and* its name is reported by
digest. `scan_irregular_name_safe` asserts the rejection and that the value is
absent from the report.

### Revision 2

**Inherited evidence bindings restored.** Reusing the frozen proof checker does
not inherit the checks around it, and v1 dropped several. `check_payload` now
restates the R6-003 preparation, request, client-argument, message and
payload-audit comparisons, the reservation and route-attribution receipts, the
verdict's task/manifest/challenge binding, the assembly and certificate receipt
payloads, and the per-stage command and budget receipts. Four resealed
mutations — `altered_request_reservation`, `altered_route_attribution`,
`altered_client_arguments`, `forged_verdict_task_binding` — are now rejected.

**Fail-closed traversal.** `publication.inventory` no longer relies on `rglob`
plus `is_file`. It walks explicitly, records any directory it cannot enumerate,
and rejects symlinks and non-regular entries rather than following or ignoring
them. An unenumerable subtree prevents acceptance. `scan_unreadable_directory`
first proves the subtree really contains a target and that listing it raises
`PermissionError`; `scan_symlink_rejected` pins the symlink policy.

**A complete checkpoint publication gate.** The recount no longer discovers
episodes by looking for seals. It requires the episode population to equal the
frozen native case set and every process log to be present, then scans one
declared bundle — episode trees, logs, suite files, checkpoint metadata, the
report, the review directory, the frozen policies and the locked sources —
against **all** episode canaries at once. `recount_missing_episode`,
`recount_missing_log` and `recount_suite_artifact_leak` each confirm the
unmutated copy passes first, then require the mutated one to fail.

**Validated scan provenance.** The audit now runs in two phases. Findings are
recomputed first, so a disclosure keeps diagnostic priority over any incidental
mismatch. Inventory completeness, uniqueness, recorded hashes and lengths are
then validated after the evidence bindings, so those keep their own diagnostics.
Duplicate paths, entries naming neither a present file nor a frozen build
product, and forged hashes or sizes are rejected
(`duplicate_scan_target`, `phantom_scan_target`, `forged_scan_hash_and_size`).
`events.ndjson` is handled explicitly: its scan-time input is the exact byte
prefix before the terminal receipt. The frozen ephemeral inventory travels with
a resealed copy, and an entry that cannot be recomputed is reported as
`recorded_not_recomputed`, never counted as verified work.

**Both credential representations.** Base64 of the complete `Bearer <token>`
value does not contain base64 of the token — the alignment differs — so v1's
token-only patterns missed an ordinary encoding of the value actually
transmitted. Patterns are now generated for both representations, giving 14
patterns over 7 declared forms, with overlapping matches reported separately
rather than de-duplicated. `scan_authorization_representation` asserts the
alignment precondition, that token-only patterns miss it, and that decoding
reproduces the exact header.

Two qualifications from the review are also addressed. `publication.safe_record`
now takes an explicit allowed key set and rejects any other key, so the
structural claim matches what the helper establishes
(`safe_record_exact_keys`). A path that would itself re-emit the value is
reported by digest with `path: null` and counts as a `path`-stream disclosure,
so a canary-bearing filename fails the initial scan instead of only the later
report scan (`scan_path_disclosure`).

## The four decisions

### 1. Private credential file, derived canary

The canary is `R6CANARY` followed by `sha256(<domain>:<nonce>)`, with domain
`r6-004-synthetic-canary-v1` and a fresh 64-hex nonce per episode.
[`credential.py`](credential.py) is the frozen generator. Publication records
retain the nonce and the domain, never the value, so a reviewer reconstructs the
canary while the literal string is absent from every accepted artifact. A real
credential is not derivable from a published nonce, so this reconstructibility
is a review property rather than a disclosure; the exemption list is empty.

`credential.delivery` materializes `Bearer <canary>` in a mode-0600 file under a
fresh temporary directory outside the artifact tree, yields it, and removes the
directory afterwards. The episode mounts that file read-only at `/credential`
and passes the adapter only the guest path. The value never enters argv or the
environment: Bubblewrap `--setenv` arguments and the stage command record would
both retain it. The auditor re-reads the recorded command, confirms the mount
host path lies outside the run, confirms that path no longer exists, and
requires the canary and its header form to be absent from the joined argv.

### 2. Publication acceptance is separate from proof acceptance

Three predicates are recorded in three artifacts and never collapsed:

| Predicate | Artifact | Meaning |
| --- | --- | --- |
| Exact credential receipt | `credential-receipt.json` | the endpoint's digest of the header it actually read equals the digest derived from the retained nonce |
| Publication non-disclosure | `publication-scan.json`, `publication-final.json` | zero canary occurrences across the walked inventory, with nothing incompletely scanned and nothing unenumerable |
| Proof validation | `verdict.json` | the frozen shared checker's declaration, type, reference and axiom requirements |

`credential-summary.json` carries the proof and receipt predicates and the
recorded failure boundary; it is written before the scan and never states a
publication result. The terminal event carries the three outcomes plus the
digests of those records, and the seal is written last. A rejected episode keeps
its seal, its receipt record and its scan report; nothing is deleted to make a
scan pass.

### 3. Independently derived inventory, declared coverage, explicit order

[`publication.py`](publication.py) walks the declared roots itself. A reported
target list is never consulted. A recorded hash, count or component name is
never *trusted*: the auditor reads each one precisely in order to compare it
with its own recomputation.

- Representations: the bare token and the complete Authorization value.
- Encoded forms: `utf-8`, `utf-8-lower`, `utf-8-upper`, `base64`, `hex`,
  `utf-16-le`, `utf-16-be`. Each of the 14 patterns is exercised individually.
- Decompression limit: 64 MiB. A member exceeding it is recorded as
  incompletely scanned and prevents acceptance; it is never skipped.
- Unreadable files, unenumerable directories, symlinks and non-regular entries
  all prevent acceptance.
- Findings record `path` (or `null`), `path_sha256`, `stream`, `representation`,
  `form` and `offset` — never the matching bytes.

All of that is declared in the [frozen policy](policies/credential-http-v3.json)
— representations, forms, decompression limit, and the symlink, non-regular,
unenumerable-directory, unreadable-artifact and canary-bearing-path policies —
and `credential_contract.config()` rejects any episode or audit whose scanner
constants have drifted from that declaration.

Finalization order is `artifacts → scan → scan_report → report_scan →
terminal_event → seal`. The scan runs after every other artifact is written. The
report is then scanned separately, and every write after that point is
restricted to an exact key set of digests, counts and booleans, checked by
`publication.safe_record`. That restriction is what replaces a self-referential
hash of the report inside itself.

The episode's own scan covers the run tree. The checkpoint recount covers the
whole declared bundle, including the process logs the episode cannot scan while
its own stdout is open.

### 4. Versioned adapter and auditor, reused proof checker

[`credential_http.py`](credential_http.py), [`credential_episode.py`](credential_episode.py)
and [`credential_audit.py`](credential_audit.py) are versioned separately.
R6-003's adapter, policy, locks and episodes are untouched and still audited
here. The pinned Python runtime, the frozen `farkas-lia-v1` prompt, the
request/envelope contract in `provider_payload.py` and the certificate assembler
are reused by hash.

The proof block is the frozen `envelope_proof_audit.audit`; this checkpoint adds
no third copy. Reusing frozen components has a visible consequence for
attribution, and both instances are audited rather than papered over: the
certificate envelope binds the R6-003 policy hash, and the `recovery_finished`
receipt carries the R6-003 route name, because the assembler and the
consumption driver are that unchanged component. The `recovery_started` receipt
names this policy, `search-policy.json` records its identity, and the auditor
requires the `previous_policy_sha256` chain between them.

## The reflected-canary control

The canned endpoint echoes the received Authorization value into an HTTP error
body. The adapter retains that body exactly as it retains any other response, so
the disclosure arrives through the ordinary failure-recording path rather than
through a hand-edited file. The episode fails at `provider-response` with
`provider_http_error`, the scan finds the canary in
`stages/proposal-1/output/provider-response.json`, and publication is rejected
while the sealed evidence is preserved. The auditor asserts the precondition —
that the value really is in the retained response bytes — before requiring the
rejection, so the control cannot pass vacuously.

That retained response is Git-visible. It is deliberately tainted **synthetic**
research evidence, and the recount reports it as such: one expected synthetic
disclosure in a rejected control, zero unexpected disclosures, and zero
disclosures in any publication-accepted episode. No blanket zero is claimed for
the bundle.

Run with `-B` so no bytecode is written into the scanned publication tree. Each
run directory must be new. `--development-policy-dir` writes disposable
versioned locks under the ignored R6 cache for iteration; the checkpoint itself
runs against the frozen policy, because the retained R6-003 episodes record the
frozen R6-003 policy path in their own provenance. Suites start red, write each
completed case immediately, and assert exact case-name sets with no duplicates
before writing green.

## Limits

These are controlled local checks. They do not establish that a provider SDK, an
HTTPS client, or a real endpoint preserves these properties; that boundary is
tested again at the HTTPS handoff, as the requirements specify. The scan covers
the declared representations and encoded forms over the walked inventory; it is
not a proof of protection against every transformation, partial disclosure, or a
hostile host. The receipt digest is a synthetic-canary commitment and is not a
scheme for publishing fingerprints of real credentials. Source and binary hashes
bind retained bytes; compilation and host execution remain trusted. D1-only
native coverage is deliberate for a transport change; C8 remains covered through
the historical audits.
