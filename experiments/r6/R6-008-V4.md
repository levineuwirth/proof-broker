## The fourth review's findings

**1 (P1) — lifecycle ownership followed successful returns.** Now: an
`attempt_id` is chosen and recorded (`reservation_attempted`) before any
ledger effect and stored in the reservation row. An uncertain `reserve()`
return is resolved by `find_open(attempt_id)` against the ledger, never by
the exception; a recovered reservation is *not* launched but reconciled as a
pre-launch release; if the ledger itself cannot answer, `reservation_state:
unknown` is reported with `attempts_reserved: null`. All receipt writes after
reservation sit inside the reconciliation lifecycle. `reconcile` owns the
disposition the moment the terminal row commits — evidence copies that fail
afterwards are `evidence_write_failures`, not an open reservation — and an
uncertain `book.reconcile` return is resolved by `find_terminal`. The slot is
closed by its marker *before* the terminal row is appended, so no sender can
act between the two; a marker without a row is completed on the next call.
The ledger's `_rows` never writes; a head behind the rows is a floor that the
next append catches up.

**2 (P1) — an object was not a safe record.** `read_record` validates
required fields and types per record kind (`process`, `http`, `server`) and
turns a failure into retained evidence (`error: schema`, the offending
fields, the bytes' digest). `accounting_for` is total: it indexes nothing it
has not validated, and the last-resort path wraps it so that accounting can
never throw while an earlier failure is being recorded.

**3 (P1) — the scanner's own root labels disclosed the token.** Inventory
entries carry a root *index*; root names in the report are the frozen
scanner's own labels; absolute paths live only in the in-memory lookup. The
assembled report and the printed summary are scanned with the frozen
patterns before anything leaves the process; a hit writes a refusal instead.
Control `canary_bearing_root_name`: a root named by the token, zero copies
in report or stdout, the run still bound. The two-root collision repair is
preserved.

**4 (P2) — short ledger appends.** One `write_all` serves exclusive creation
and append; the head advances only after a complete, fsynced append; a
partial trailing line is `campaign_ledger_partial_append` on parse and is
discarded under the head floor on the next locked read. Controls:
`ledger_partial_append_recovered` and the two sweep rows above.

**5 (P2) — unknown turned into zero.** `live_transmissions_consumed` is
gone; `allowance_consumed` is the one allowance field, `null` when unknown,
with `live` recorded beside it. Controlled in `counters_separate`.

**6 (P2) — auditor bindings.** `campaign_episode` is bound as a campaign
module; per-entry scan streams are compared with the fresh scan; the
durable-completion timestamp is required for every revision that promised it
(v1 keeps its creation-only qualification); revision-4 markers are bound by
the row's `marker_sha256` and the reservation's `attempt_id` by the
`reservation_attempted` receipt. Controls: `retained_episode_module_altered`,
`scan_stream_mutation`, `missing_durability_field` (predicate-level, as the
review's was), `marker_digest_rebound`, `attempt_identity_rebound`.

Records use revision-specific names from here on
(`R6-008-V4-*.json`, `R6-008-V4-OPERATOR-SCAN-CONTROLS.json`); the shared
operator record replaced at revision 3 is noted in that report.

## What is not established

No live transmission has happened under this policy. The live ledger, the
operator-scan binding on a real credential, and the `unknown` path after a
real partial send are exercised by controls, fault injection and loopback
actors only. Signing (`campaign_contract.py sign`) creates the live ledger;
the first live run under it should be a single transmission, audited before
any cohort work.
