## 2. P1 — unreadable directories disappear from the scan

Location: [publication.py](../../publication.py), `inventory`, lines 77–88.

`Path.rglob` plus `is_file()` does not provide a fail-closed inventory walk. A
probe creates a directory containing the exact canary, makes that directory
unreadable, and first confirms that listing it raises `PermissionError`.
`publication.scan` nevertheless returns:

```json
{"accepted": true, "files_scanned": 0, "incomplete": []}
```

The existing unreadable-file control passes, but it cannot expose a failure to
discover the file in the first place. Use traversal with explicit error
handling; inability to enumerate a subtree must prevent publication acceptance.
Declare and enforce a policy for symlinks and non-regular entries as well.
Retain a control that proves the unreadable subtree actually contains a target.

## 3. P1 — the checkpoint recount is not a complete publication gate

Location: [credential_final_checks.py](credential_final_checks.py), lines
51–81 and 93–95; [test_credentials.py](../../test_credentials.py), `native`.

The recount discovers episodes by finding existing `seal.json` files. It does
not require that the resulting population equals the frozen native case set.
It also treats an absent outer log as a clean zero-file scan and does not scan
suite/checkpoint-level artifacts for each canary.

All three disposable recount mutations return `passed: true`:

| Mutation | Recount result |
| --- | --- |

There is also an existing reporting error: the recount writes
`canary_values_found_in_publication: 0` literally. Its own per-episode record
contains the reflected case's one disclosure. The reflected response is
Git-visible in the proposed checkpoint. It is valid to retain this deliberately
tainted **synthetic** control as research evidence, but the blanket zero claim
is false for that population.

Require the exact episode/seal/log population and a complete publication bundle
inventory, including suite files, checkpoint metadata and review reports. Scan
the final selection against all relevant synthetic canaries. Report observed
counts by population: expected synthetic disclosures in rejected controls,
unexpected disclosures, and disclosures among publication-accepted episodes.
Do not silently exclude the deliberate negative from the headline population.

## 4. P2 — scan provenance and inventory claims are not validated

Location: [credential_audit.py](../../credential_audit.py), lines 288–316.

I do not recommend accepting the proposed hash exception as the final design.
A seal binds the file and the report as separate byte strings; it does not
establish that the hash claimed inside the report describes that file.

The review demonstrates three accepted mutations:

| Mutation | Accepted claim |
| --- | --- |
| `forged_scan_hash_and_size` | `accounting.json` has digest zero and length 987,654,321 in the scan report |
| `phantom_scan_target` | A nonexistent clean target increases `files_scanned` from 193 to 194 |
| `duplicate_scan_target` | A duplicate entry is silently collapsed by the dictionary construction |

Compare findings/status first, then validate hashes and lengths. That preserves
the intended disclosure diagnostics while rejecting false provenance. Handle
`events.ndjson` explicitly: the scan-time input is the exact byte prefix before
the final appended receipt. Missing build products in a retained-only copy need
an explicit, frozen ephemeral inventory and a distinction between recorded and
recomputed coverage. An arbitrary absent entry must not count as verified work.
Reject duplicate paths and unexpected inventory entries.

## 5. P2 — the full encoded Authorization value is outside current coverage

Location: [publication.py](../../publication.py), `forms`, lines 29–37.

The patterns are generated for the token alone. Base64 encoding the entire
`Bearer <canary>` value changes the alignment, so it does not contain
`base64(canary)`. A file holding only that encoded header passes with zero
findings; decoding it reproduces the exact header. This is an ordinary declared
encoding of the value actually transmitted, not an arbitrary obfuscation.

Generate the declared forms for both the token and complete Authorization value,
with explicit accounting for overlapping matches. Freeze controls for both
representations before the live credential channel inherits the scanner.

## Additional finalization qualifications

`publication.safe_record({canary: True})` returns true: dictionary keys are only
checked for being strings, not for membership in a fixed set. The claimed
structural guarantee is therefore stronger than that helper establishes.
Current fixed payload construction and the full auditor's separate scans of
post-scan files limit the immediate consequence; this probe is **not** a
demonstrated full-auditor disclosure bypass. Enforce exact allowed keys and keep
the byte-level final checks.

The scanner also copies filenames into its report. A clean-content file whose
name contains the canary yields an accepted initial scan and a report that
re-emits the value. The separate report scan is the later detector, but the
claim that findings cannot re-emit a value needs qualification and a control.
Use safe identifiers for canary-bearing paths in diagnostics intended for
publication, and fail publication without rewriting sealed evidence.
