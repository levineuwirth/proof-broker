## The sixth review's findings

**1 (P2) — summary bindings** *(auditor only)*. New case
`summary:bound_to_audited_records` per run: the summary's `task_id` must be
the task, `search_policy` and `mode` the run's policy and mode, and its
embedded `accounting` object must equal the independently recomputed
`accounting.json`. Three separate controls, each on a copy that accepts
first: embedded `evidence_complete` flipped; embedded `allowance_consumed`
1→0; `task_id` set to the registered C8 id. Each rejected at that case.

**2 (P2) — recovery ordering** *(locked)*. In `reconcile`, a row recovered by
`find_terminal` is assigned to the lifecycle *before* the evidence snapshot is
read; a failed snapshot is an evidence failure (`ledger-after` missing,
`evidence_complete: false`) with the known disposition retained. Sweep row
`reconcile_recovery_snapshot_failure` (compound: terminal head failure, then
snapshot failure): `send_grant`, allowance 1, `ledger_reconciled: true`,
`evidence_complete: false`, sealed `episode_rejected`.

**3 (P2) — repeated marker recovery** *(locked)*. When reconciliation
completes from a valid marker, any torn marker left beside it by an earlier
interrupted repair stays associated with the row (`torn_marker`); the
auditor's slot rule derives the permitted layout from the row. Control
`marker_recovery_complete_and_torn` now also covers the interrupted repair
(seven-byte `release.json`, valid `unknown.json`, terminal append fails,
retry → `unknown / completed_from_marker / torn_marker: release.json`), and
the torn `unknown.json` safe stop (`campaign_marker_torn_unrecoverable`,
reservation left open for the operator — an explicit limitation, not an
automatic recovery). The audit controls include a positive for the
repeated-recovery layout.
