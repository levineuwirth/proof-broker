## The extraction

The source is the retained pristine `Bracket.lean` (`03b4d5ca…`, VerInf
`c07e03c9…`), never a checkout. A site is an `omega` token in code position —
block comments (nested), line comments and string literals are masked, and an
identifier merely containing `omega` is not a token. Its identity is the byte
span of the token: four bare `omega` lines repeat verbatim (71, 98, 101, 178),
so line text cannot identify a site. Each site carries its containing
declaration (the family unit), a syntactic form from a frozen first-match
pattern table, and an exposure record. Extraction from the pinned bytes must
reproduce the frozen fifteen-row table exactly; a removed or added site is a
refusal, not a re-count.

## The extended anchor

[`CaptureSite.lean`](capture/CaptureSite.lean) is the R6-000 helper with its
two fixed identities made parameters: `r6_capture_human "<saved declaration>"
"<site id>"`. The capture is of the goal state at the site, whatever syntax
surrounds it — a named or anonymous `have`, a bare closer, a post-`simp`
closer, an inline term argument, a `calc` step — so the eight non-`have`
forms need no synthesized `have`. Control `capture_helper_differs_only_by_parameterization`
diffs the two helpers and requires that the only removed lines are the
signature, the fixed name and the fixed task id. The permitted modification
per site is exactly two hunks: the trusted `import Capture` and the token at
its byte span (`permitted_modification_is_one_token_and_one_import`, checked
against every retained `permitted.patch`).

**Line 70 reproduces the R6-000 control.** The generalized capture at line 70
yields a local context equal to `verinf-d1-70`'s frozen
`context/local-context.json` in every field except the two identity fields,
the same byte span, the same goal source, and a closed local type whose
replay digest equals the control's (`26b1db6f…`); the whole declaration's type
digest and axioms agree (`line70_reproduces_the_r6_000_control`).

## The freeze

Per family, one original export validated against itself; per site, the
instrumented file compiled with the site helper, exported with the saved
declaration, and replayed twice — baseline against the site export (source
binding) and the site export against itself with the local/whole dependency
required — as for R6-000. A site whose capture, compilation, export or replay
fails is excluded with the failing sandbox stage, its exit code, and the
digests and first lines of its stdout and stderr; nothing is retried or
hand-adjusted. Control `exclusion_records_failing_stage_and_stderr` drives a
site whose saved name is its own containing declaration through the real
path: the kernel rejects the duplicate constant, the result is `excluded` at
`task-build` with the stdout digest, and the census directory is untouched.

**All fifteen sites were admitted.** Every replay accepted with axioms within
the allowlist; every manifest validates against the site schema and binds its
artifacts, the shared artifacts, the family baseline, the capture helper and
the vendor lock (`site_manifests_bound`, `freeze_bound_to_its_sources`).

## Proposed membership

[membership.json](tasks/census-v1/membership.json): primary = all fifteen
admitted sites, in four families (4 / 4 / 6 / 1); exposed = `bracket-l070`,
stratified, not removed; excluded = none; hash-bound to the census record and
to every site manifest (`membership_partitions_and_binds_the_census`). Its
status is *proposed*: membership is frozen by review approval before the
deterministic arm or any learned draw. Whether the exposed site and the
symmetric branch pairs stay in the primary set or are reported as strata is the
decision this record puts in front of the review; the checkpoint records the
population either way.

## What is not established, and what is next

No episode has run on any census site: the cohort driver, the proposal
overlay and the deterministic route are still bound to the two registered
R6-000/R6-002 tasks, and their generalization to site tasks is the next
locked change, to be exercised first by the deterministic arm on every
primary site (canned, no model call), then by the frozen analysis code on
canned records. The census is one file at one commit; eight draws per site do
not add independent families, and the four families support no
repository-population claim.
