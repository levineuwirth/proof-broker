Status: checkpoint passed, ready for review, 2026-09-09. **92 checks pass:
28 focused / 17 native episodes / 32 artifact audits / 15 outer-gate controls.**
This checkpoint uses canned responses and synthetic credentials. It enables no
live endpoint and authorizes no spending. The
[pre-work inventory](reviews/2026-09-09/R6-006-PRESERVATION.json) preserves all

## The missing enforcement

R6-005's retained pricing source could be checked offline, but its transport did
not require that check. R6-006 places it in two executing paths:

1. `priced_budget.reserve` re-extracts and checks the source, policy, request,
   applicable rates and capture age before opening the reservation ledger.
2. The new HTTPS actor independently repeats admission against its mounted
   sources and the exact request/body. It validates the permit and ledger before
   reading the credential or starting a connection. It uses the admitted
   in-memory body for the existing R6-005 handoff, with no payload reread.

The actor does not trust a recorded `accepted: true`. Missing permits, forged
admission fields and altered amounts have their own rejection codes. Source
changes after host admission are checked again inside the actor. Publication,
credential receipt, pricing admission, certificate verification and proof replay
remain separate observations.

## Dated candidate and its rate basis

The canned configuration uses `gpt-5.4-2026-03-05`, requested and allowed as the
same dated ID. This is an agent-selected candidate; author selection of the
measurement cohort and any spending approval remain pending. A dated provider
identifier is not a hash of weights or an attestation of inference. Account
access and actual provider response-ID behavior have not been tested.

The [official model page](https://developers.openai.com/api/docs/models/gpt-5.4)
establishes the dated ID and input/cached-input/output rates. The
[official caching guide](https://developers.openai.com/api/docs/guides/prompt-caching)
supplies the missing rule: models in its earlier-model column have no additional
cache-write charge. Applying that rule to GPT-5.4 leaves the ordinary input
charge in place; a cache write is not free. Both full pages, retrieval receipts
and reproducible extracts are retained under
[sources/pricing-approved-v1](sources/pricing-approved-v1).

The source pins cover both raw bytes and extracted sections. Changed numeric
rates, changed conditions and raw-only changes all require a new reviewed
binding. Admission uses a maximum observed capture age of 24 hours, five
seconds of future clock tolerance and a 60-second permit lifetime. Those are
project choices, not provider guarantees. Audits use the recorded admission
time, rather than expiring historical evidence when the audit runs later.

Each episode first enrolls an immutable `pricing-origin/` copy, whose file-map
digest is bound into `search-policy.json` and the episode-start receipt. Host
and actor source copies derive from that enrolled input. The auditor uses the
episode's retained origin, not whatever a source path happens to contain later.
An archival control makes that external path unavailable and still audits the
episode. A fresh capture with unchanged approved page bytes may be supplied to
the runner through `--pricing-sources`; changed raw bytes require review of a
new policy binding. Captures are never refreshed in place.

Capture timestamps and host clocks remain local observations. The gate does
not prove that a retrieval occurred, that the website is authoritative about a
particular account's bill, or that prices remained unchanged between retrieval
and send. `billing_guarantee` remains false; the input-token bound retains
R6-005's byte-plus-framing assumption. Unknown usage remains null and a failed
attempt releases no reservation.

## Request bytes and the unchanged proof consumer

Admission distinguishes canonical data hashing from HTTP entity bytes. The
frozen HTTP encoder escapes non-ASCII characters; its output differs from the
canonical UTF-8 JSON used for record hashing. The `wire_encoding_distinct`
control asserts that its real input contains non-ASCII text, checks both byte
representations differ, and verifies that the permit binds the actual encoder.
A development native run caught this mismatch by rejecting before connection.

The model-visible input remains the admitted `le`/`eq` Farkas problem and frozen
prompt. Model/source context selection, arithmetic row semantics, downstream
task identities and the R6-003 certificate consumer are unchanged. Certificates
continue to name that consumer's policy. The proposer remains truthfully
`canned_provider_response`; no model searched for these witnesses.

The new verdict restores `proof_replayed: true`, checked alongside the retained
local/containing reports by the shared proof auditor. `derivation_replayed`
remains false and the residual closer remains `omega`. C8 still tests a
statement-identical containing wrapper; D1 tests a local obligation embedded in
the larger real downstream declaration.

## Reproduce and review

Re-audit the complete retained checkpoint and its already recorded outer
controls without running new native episodes:

```bash
python3 -B experiments/r6/reviews/2026-09-09/pricing_gates.py \
  --run-dir experiments/r6/pricing-runs/checkpoint-v1 \
  --gate-file experiments/r6/reviews/2026-09-09/R6-006-GATES.json \
  --output /tmp/r6-006-public-recount.json
```

Adding `--controls` re-executes the 15 outer probes; use a fresh gate-file path
and output path to preserve the reviewed record. The independent byte/count
checks are reproducible without Lean execution:

```bash
python3 -B experiments/r6/reviews/2026-09-09/pricing_final_checks.py \
  --run-dir experiments/r6/pricing-runs/checkpoint-v1 \
  --gate-record experiments/r6/reviews/2026-09-09/R6-006-PUBLIC-GATE.json \
  --output /tmp/r6-006-preflight.json
```

A new native run requires the existing R6 toolchain, user systemd supervision
and a source capture within the admission window. Fetch into a new directory;
unchanged approved bytes permit a fresh receipt, while a changed page requires
review and a new policy binding before admission:

```bash
python3 -B experiments/r6/pricing_capture.py \
  --output /tmp/r6-006-fresh-pricing
python3 -B experiments/r6/test_pricing.py \
  --run-dir experiments/r6/.cache/r6-006-reproduction \
  --pricing-sources /tmp/r6-006-fresh-pricing
```

The complete recount deliberately requires the original build products.
Retained-only episode auditing is a narrower operation; it does not upgrade
missing build-product observations into recomputed facts. Changes to any
locked module require a new policy/source-lock version and fresh native
evidence. Review helpers under `reviews/2026-09-09/` are outside that lock.
