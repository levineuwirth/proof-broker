## The third review's six findings

**1 (P1) — an exception after reservation could leave it open while the
summary claimed reconciliation.** The reservation is now owned by an explicit
lifecycle record created before `reserve` and passed through `invoke` to
`execute`; everything after reservation — copying transport inputs, building
mounts, launching the stage — sits under one block whose every exit attempts
reconciliation; a reconciliation failure is itself recorded
(`reconciliation_failed` event, `ledger_reconciled: false`,
`failure_category: reconciliation_failure`) with the reservation reported as
open, never inferred absent. `read_record` accepts only JSON objects and turns
missing, truncated, malformed, unreadable or non-object records into
evidence; hashing of unavailable bytes is guarded; the ledger's grant reader
treats `OSError` as an unreadable grant. A failure before any sender was
launched — established by the absence of the stage's `command.json`, which
the launcher writes before spawning anything — is a `release` with reason
`pre_launch_failure`; a failure after launch still needs established
termination. Controls: `lifecycle_pre_launch_failure_released` (the review's
copy failure), `lifecycle_non_object_records_consumed` (`[1]` in either
record), `lifecycle_reconciliation_failure_reported`,
`unreadable_records_are_evidence` (mode-000 record and grant).

**2 (P1) — the auditor did not reconstruct authority and release.** Three new
cases per run. `ledger:disposition_derived` recomputes termination with the
ledger's predicate from the hash-bound supervisor record, reads the grant from
the **authoritative** slot with the revision's grant domain, and derives the
expected row kind (grant → `send_grant`; unreadable grant → `unknown`; never
launched → `release`; established termination and zero counters → `release`;
else `unknown`) — the recorded kind and flags must match.
`slot:authoritative_matches_retained` requires exactly the expected marker
in the ledger-side slot, bound to the reservation (grant) or to the terminal
row hash (release/unknown), byte-equal to the run's copy.
`mounts:authority_bound` parses the recorded command: `/ledger.ndjson` is a
`--ro-bind` whose source ends with the policy-derived `ledger_path`,
`/grant` is a `--bind` of exactly that root's `ledger_slots/<reservation_id>`
and equals `grant_slot`, the run-local inputs come from the recorded run
directory, and only `/out` and `/grant` are writable. Controls, using the
review's own mutation code copied in: `release_despite_live_workload`
(coherent rewrite of every mirror), `authoritative_grant_altered`,
`authoritative_marker_altered`, `ledger_mount_changed`, `grant_mount_changed`.

**3 (P2) — missing transport records invented zeros.** `accounting_for` now
takes the lifecycle record: `transport_record_observed` says whether the
sender's record exists; `connection_attempts`, `headers_started`,
`transmissions_observed`, `transmissions_returned` and `endpoint_receipts`
are the sender's own counts or `null`; `grant_committed` and `send_outcome`
come from the authoritative reconciliation when it exists;
`allowance_consumed` is the ledger disposition, distinct from
`transmissions_observed`. The interrupted-record control now inspects
accounting: grant committed, outcome unknown, allowance consumed, counters
null. The fallback accounting in `execute` is built from the lifecycle
record, never a constant.

**4 (P2) — a short write was reported durable.** `write_exclusive` loops
until every byte is written, refuses zero progress (`campaign_write_stalled`),
and `commit_grant` requires the full length. The final-name marker stays
whatever happens, so a failure after a partial write leaves an unreadable
grant that reconciliation consumes as `unknown`. The actor wraps the commit:
a write failure is `campaign_grant_write_failure`, and no header is sent.
Controls: `grant_short_write_completed` (7 bytes then the rest; a stalled
write), `grant_partial_write_failure_consumed` (7 bytes then `EIO`).

**5 (P2) — forged scan provenance survived.** `publication:recomputed` now
compares `events.ndjson` by its exact pre-terminal prefix (hash and length),
requires unique inventory paths, `files_scanned == len(inventory)`, gzip
stream counts, per-entry `scanned`/`error`/`findings`/`streams`, and each
entry's hash and length against the current file. Controls:
`scan_event_hash_forged`, `scan_event_length_forged`.

**6 (P2) — multiple scan roots collided.** The operator scan runs the frozen
scanner once per root and unions the inventories with each entry's root;
`bind_runs` keys by absolute path. Control: `two_roots_colliding_names`
(two valid sealed runs with identical relative names and different bytes,
both covered). The pilot auditor reads both report shapes.

**Version dispatch.** The auditor carries explicit rules per campaign
revision (ledger domain, purpose, termination flag, `launched`, slots, grant
domain) and reports a superseded revision as superseded, with the campaign
modules that differ from the current ones listed as an auditor/source
incompatibility — not an invalidity verdict. Upstream frozen modules must
equal the retained copies for every revision; campaign modules must equal
them for the current revision only. All three revisions audit at 73 cases;
the two superseded positives are recorded with the controls.

## What is not established

No live transmission has happened under this policy. The live ledger, the
operator-scan binding on a real credential, and the `unknown` path after a
real partial send are exercised by controls and loopback actors only.
Signing (`campaign_contract.py sign`) creates the live ledger; the first live
run under it should be a single transmission, audited before any cohort work.
