## The fifth review's findings

**1 (P1) — recovery receipts could lose ownership.** `recover_reservation`
now marks the state `unknown` before any fallible diagnostic, consults the
ledger, and on a hit retains the permit and sets `reserved` *before* any
receipt is written; the `reservation_uncertain` and `reservation_recovered`
receipts are emitted inside the guarded block that always reconciles, so a
failed receipt cannot decide whether reconciliation runs. A `reserved` state
without its permit is represented as `unknown` by accounting, never as zero
and reconciled. Sweep rows: `reservation_uncertain_event_failure` and
`reservation_recovered_event_failure` (the review's compound faults) both end
with one reservation released, `attempts_reserved: 1`, reconciled.

**2 (P1) — the scanner's error path.** Every read inside `bind_runs` is
bounded (`digest()` returns `null` on `OSError`; unreadable or malformed
inputs become `read_failures` and false verdicts), and the whole
credential-bearing operation runs under `contained()`: any exception becomes a
sanitized refusal on stdout with exit 2 and stderr discarded, so no traceback
— and no path — can leave the process. Control
`unreadable_bound_file_under_canary_root` (mode-000 precondition asserted):
exit 1, empty stderr, zero token copies in report, stdout or stderr, all four
verdicts false, `read_failures: 1`.

**3 (P2) — attempt identity mandatory.** The auditor derives the mandatory
`reservation_attempted` receipt from the declared revision (from v4: exactly
once, before `pricing_admitted`) and requires a well-formed 64-hex identity in
the permit equal to the receipt's; older revisions keep their explicit
absence rule. Controls: event removed, field removed, both removed, empty
identity — each rejected at the named case.

**4 (P2) — evidence completion defined and enforced.** Two fields now:
`reconciliation_evidence_complete` (the grant copy, `ledger-after`, the
reconciliation receipt and the `reservation_reconciled` event — the event is
now inside the recorder) and `evidence_complete`, the whole-episode predicate:
reservation state known, ledger disposition known, every reconciliation
artifact written. `finalize` requires it for `episode_finished` and for
`accepted`; the terminal payload carries it. A failed receipt after a
committed terminal row is an evidence failure with the true disposition
retained, never "Reservation left open". The auditor derives completion from
the artifacts and compares every mirror (summary, accounting, terminal
payload) against it. Controls: `finalize_requires_complete_evidence`
(proof true, evidence incomplete → `episode_rejected`), sweep row
`reservation_reconciled_event_failure`, auditor mutation
`summary_evidence_contradiction`.

**5 (P2) — torn markers.** Reconciliation parses and binds an existing marker
before trusting it; a torn marker is never the declared receipt: the
reservation is consumed as `unknown` with reason `torn_marker`, a valid
`unknown.json` written beside the torn bytes and named by the row's
`marker_sha256`. Control `marker_recovery_complete_and_torn` covers both the
completed-marker recovery and the seven-byte torn marker; the auditor's slot
case expects that layout and rejects a torn receipt bound by digest
(`torn_marker_receipt`).

Wording: `_rows` never writes the head; it may truncate and fsync a partial
trailing line.
