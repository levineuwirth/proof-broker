Status: checkpoint passed, ready for review, September 10, 2026 (Copenhagen).

## Finding and scope

The retained [GPT-5.4 model page](https://developers.openai.com/api/docs/models/gpt-5.4)
states two conditions that v1 preserved as text but did not turn into
executable pricing premises: a long-context surcharge and a regional
processing uplift. V1's actual allowance and endpoint make both inapplicable.
Its configuration also already rejects changes to those frozen values by
exact comparison with its predecessor. The defect is the missing semantic
connection between the reservation basis and the applicable tariff when
defining a subsequent policy, not demonstrated under-reservation in v1.

Revision 2 records and enforces that connection before reservation and again
inside the HTTPS actor, before credential access or connection. It excludes
both premium regimes; it does not implement their billing arithmetic.

| Source condition | Explicit project admission rule |
| --- | --- |
| Above 272,000 input tokens: 2× input and 1.5× output, for the full session, across standard/batch/flex | `input_tokens_reserved < 272000` |
| Regional processing endpoints: 10% uplift | Exact allowlist: `https`, `api.openai.com`, port 443, `/v1/responses` |

The strict project inequality is deliberately more conservative than the
source's `>272000` trigger: exactly 272,000 is rejected by this policy even
though it does not satisfy the documented surcharge trigger. The endpoint
allowlist rejects every unapproved endpoint, including unknown ones. It is
not a classifier purporting to identify every regional service.

The full-session qualification is also preserved. Admission permits one
stateless request and explicitly rejects previous-response, conversation and
context-management inputs; the existing exact message/options checks remain
in force. The token allowance still relies on the previously declared byte
ceiling plus framing assumption. This revision does not establish exact token
counting, a provider billing cap, remote receipt, or inference attestation.

## Implementation and source binding

The new [policy](policies/responses-priced-https-v2.json) records the structured
source conditions, their multipliers and scopes, the strict input bound and
the exact endpoint allowlist under `pricing_admission.applicability`.
[pricing_gate_v2.py](pricing_gate_v2.py) re-extracts the conditions from the
retained page and compares the declaration against its own reconstruction.
It then checks the actual allowance, endpoint and request. It does not trust
a declared `surcharge_applicable: false` value.

Host and actor admission records each retain the resulting applicability
evidence, separately identifying the long-context and regional predicates.
The versioned auditor recomputes those records from retained inputs. The
actor's exact policy bytes are now retained as `transport-policy.json`,
mounted read-only and independently compared with the frozen case's input.
The three new native negatives deliberately substitute an out-of-scope actor
policy; the host's frozen policy is unchanged.
The `eu.api.openai.com` substitution establishes rejection of a non-allowlisted
endpoint; no availability, regional processing or billing at that endpoint
was observed.

Both raw pages are byte-identical to v1: 419,092 bytes for the model page and
712,212 for the caching guide. The [v2 source bundle](sources/pricing-approved-v2)
contains new extracts and receipts, with the old receipt digest and original
retrieval interval preserved. New extraction time and extractor digest are
recorded separately. This is re-extraction of the retained captures, not a
new retrieval or a reset of their 24-hour admission age.

The [v2 source lock](policies/priced-harness-v2.sha256.json) freezes nine
versioned modules. It also checks the immutable v1 dependency chain. Each
episode retains v1 and v2 source provenance; the existing shared proof
checker and R6-003 consumer are reused. No v1 locked file was edited.

The requested and allowed model remains `gpt-5.4-2026-03-05`. Sampling,
endpoint, actual token allowances, retry/resource limits and rates are
unchanged. The conditional reservation remains **102,400 micro-USD
($0.102400)**. Dated provider identity remains distinct from a model-content
hash or an attestation of inference. Live selection and spending remain
pending.

[checkpoint.json](pricing-v2-runs/checkpoint-v2/checkpoint.json), for 105
content checks. The outer controls are evaluated after the content checkpoint
has finished, then separately hash-bound at publication. They cannot be part
of the checkpoint they are still testing.

```bash
python3 -B experiments/r6/reviews/2026-09-09/pricing_gates_v2.py \
  --run-dir experiments/r6/pricing-v2-runs/checkpoint-v2 \
  --gate-file experiments/r6/reviews/2026-09-09/R6-006-V2-GATES.json \
  --output /tmp/r6-006-v2-recount.json
```

outer controls. Adding `--controls` runs those probes again; use fresh output
and gate-file paths to preserve the reviewed records. Retained-only episode
audits keep their explicit unavailable-build-product qualification and cannot
substitute for complete original-tree coverage.

```bash

  --run-dir experiments/r6/pricing-v2-runs/checkpoint-v2 \
```
