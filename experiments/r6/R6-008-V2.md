## What this policy repairs, and what the second review changed

**1. The allowance is per authorization, counted in transmissions.**
[`campaign_ledger.py`](campaign_ledger.py) is one hash-chained ledger per
approved policy digest under `ledgers/live/`, activated when the author signs
and never otherwise; rehearsals use `ledgers/rehearsal/`. Authority now lives
beside the ledger, not in run directories:

- A reservation creates the reservation's **authoritative slot**
  (`<policy>.slots/<reservation_id>/`) atomically with the row, under the
  lock, one open reservation at a time. The sender gets that slot mounted
  writable and the authoritative ledger file mounted read-only — no snapshot
  copy decides anything.
- The send grant is committed with **`O_EXCL` on its final name**, then
  file and directory fsync, after certificate verification and before the
  first header byte. Two racing writers get exactly one grant; the loser is
  refused with `campaign_grant_slot_used`. Both the grant's creation and its
  durable completion are timed (`grant_created_at_ns`, `grant_durable_at_ns`).
- Reconciliation closes the slot with a terminal marker (`release.json` or
  `unknown.json`; the grant file itself for a consumed slot). A replayed
  permit — same permit, old snapshot, fresh run directory, the review's
  loopback reproduction — is refused before any connection, both before and
  after reconciliation; a used permit against the authoritative ledger is
  refused as `campaign_permit_not_last_row`.
- **Release requires established termination**: a supervisor record with an
  integer exit code, `workload_empty_after_cleanup: true`, no monitor or
  observation error and the sandbox accounting scope. An empty record, a
  live workload, a monitor error or an exit code alone leaves the slot
  consumed as `unknown`. Counters can confirm a release, never establish one;
  counters that claim a send without a grant are `unknown`.
- An unreadable or foreign grant file is `unknown`, consumed.
- Activation, head replacement, appends and slot creation all fsync the
  directory. Power loss is not simulated.

**2. Activation is bound to the authorization it serves.** Every activation
records its `purpose` and the exact authorization record; `check_activation`
requires purpose equality with the mode and record equality with the policy
(`authorization` for live, `ledger.rehearsal_authorization` for rehearsal),
plus limit equality. The host checks it in `live_permitted`; the actor checks
it in `verify_permit` before the pricing check and the credential read. The
review's substitution — a synthetic live policy over a rehearsal activation
for the same bytes — now stops at `campaign_activation_purpose` with zero
connections.

**3. One authorization-scope function** (`authorization_scope`), run by host
and actor; zero money and an empty approver are rejected identically.

**4. The credential read is inside the actor's boundary**; a malformed file
is a classified `credential_format` record with zero connections and an
empty stderr.

**5. Local send and remote receipt are two predicates**; attempt and
transmission counters are separate; the usage-priced estimate is
`live_usage_ceiling_usd`, not a cost.

**6. Attribution passes through the consumer; the supervisor owns receipts.**
Rehearsals keep `--unshare-net` while exercising the same slot.

**7. Every failure finalizes, including interrupted records.** `reconcile`
reads the process and transport records through `read_record`, which turns a
missing, truncated or malformed file into retained evidence
(`record_read_failures`); the slot decides regardless. `invoke` reconciles
the reservation whatever stops the stage launch, and `execute` has a
last-resort handler so that scan, terminal event and seal happen on every
path. The review's interruption — committed grant, `http.json` containing
`{`, killed stage — now yields `send_grant / send_outcome unknown`, a sealed
`episode_rejected` run and a closed reservation.

**8. The operator scan binds its population and sealed bytes.**
[`operator_disclosure_scan.py --bind-runs`](reviews/2026-09-13/operator_disclosure_scan.py)
now records four separate verdicts per run — every file of the run present
in the scan inventory at its current digest; the seal present with every
retained hash matching and no unlisted file; the commitment record among the
sealed files at its sealed hash; the commitment recomputed from the operator's
file — and exits 0 only when all hold and the scan is accepted. Receipts carry
digests, counts, booleans and scanner-labelled names only.
[Controls](reviews/2026-09-13/operator_scan_controls.py): baseline accepted;
unscanned run, missing seal, record changed after sealing, wrong credential
and a disclosure planted in a bound run each rejected on their own verdict
([record](reviews/2026-09-13/R6-008-OPERATOR-SCAN-CONTROLS.json)).

**9. A reviewed signing procedure.** `campaign_contract.sign(approved_by,
approved_utc)` verifies the sources under the disabled policy, retains the
disabled bytes as `responses-campaign-v2.checkpoint.json`, writes the signed
policy under the same lock, and only then activates its live ledger and a
rehearsal ledger. The control exercises it on a temporary copy, including
the host's refusal of a rehearsal activation placed where the live one
belongs.

## What is not established

No live transmission has happened under this policy. The live ledger, the
operator-scan binding on a real credential, and the `unknown` path after a
real partial send are exercised by controls and loopback actors only. Signing
creates the live ledger; the first live run under it should be a single
transmission, audited before any cohort work.
