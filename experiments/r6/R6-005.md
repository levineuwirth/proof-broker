## Decisions and their scope

The configured default is OpenAI Responses, model ID `gpt-5.6-sol`, reasoning
effort `medium`, standard service tier, 4,096 maximum output tokens, one
attempt per episode, zero automatic retries, no redirects and a $5 local
reservation ceiling. Temperature, top-p and seed are omitted explicitly.
Sampling is not claimed deterministic. The model/cap were offered for optional
author selection; these are agent-selected configuration defaults, not an
authorization to spend money.

The [model reference](https://developers.openai.com/api/docs/models/gpt-5.6-sol),
inspected 2026-09-09, lists `gpt-5.6-sol` without a separate dated snapshot.
The policy therefore freezes a requested identifier and a response-ID allowlist;
it does **not** establish an immutable model revision. The API itself is an
unversioned `/v1/responses` interface. Provider availability and account access
are untested. A dated alternative exists in the
[GPT-5.4 model reference](https://developers.openai.com/api/docs/models/gpt-5.4)
(`gpt-5.4-2026-03-05`); changing the selection would require another policy.

The [Responses reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)
states that `max_output_tokens` includes reasoning and visible output. This
policy requests `service_tier: default`, `store: false`, no tools, no streaming,
no background processing and disabled truncation. `store: false` is an API
retrieval setting, not a claim of zero provider retention. The returned service
tier is checked independently because the documented response field can differ
from the requested tier.

## Resource and monetary accounting

Before transport, admit at most 12,288 UTF-8 message bytes, reserve 16,384 input
tokens and 4,096 output tokens, and durably append the reservation under a file
lock. Reserve 5 micro-USD per input token and 20 per output token: 163,840
micro-USD ($0.163840) per attempt. These input rates include the documented
cache-write rate rather than assuming a cache discount. The same model page
lists uncached input $4, cached input $0.40 and output $20 per million tokens;
cache writes cost 1.25 times uncached input. Prices must be refreshed before a
live pilot.

The input bound is a **byte-ceiling plus framing assumption**, not an exact
provider token count. The record says `billing_guarantee: false`. The local
ledger enforces its reservation ceiling; this does not create a provider-side
spending limit. Unknown usage is null, failed or unknown requests do not refund
the reservation, and every new attempt needs another reservation. The canned
matrix uses independent simulated episode ledgers; it is not one two-request
campaign. Campaign exhaustion is a separate control.

The actor is limited to 60 seconds wall time, 5 seconds CPU, 384 MiB memory,
4 MiB retained stage output, a 30-second socket timeout, a 32 KiB request body
and a 256 KiB response body. Socket timeout and whole-process timeout have
different meanings. Actual live-call count and actual live cost are both known
zero; canned usage and a priced usage ceiling are recorded separately.

Each `<case>.log` records Python progress and the case result. It is not an
OS-level capture of every setup subprocess: build diagnostics also reached the
caller console, before this case's canary was created. All supervised stage
stdout/stderr files are retained in the episode. Publication claims cover the
declared walked artifact inventory, not an unrecorded host-console history.

## HTTPS boundary

`live_https.client_context` requires chain verification, hostname verification,
TLS 1.2 or later, and HTTP/1.1 ALPN. The client uses the pinned Python/OpenSSL
runtime and direct `HTTPSConnection`; it reads no proxy or credential environment.
The private credential file is mode 0600, mounted read-only, never copied into
the run, and removed after the attempt. The public-root bundle proposed for a
future live client is hash-recorded separately from the synthetic test root.

The canned fixture changes two things explicitly: the TCP connection reaches
loopback inside the network namespace, and the client trusts a fresh synthetic
CA. SNI, certificate hostname verification and the HTTP Host remain
`api.openai.com`. The private CA/server keys stay outside publication artifacts.
The TLS handshake completes before the client sends Authorization or body
bytes. The entity body is captured at `HTTPSConnection.send`, and the local
TLS receiver separately records what it received. This tests real local TLS;
it does not test the deployed provider chain, remote receipt or inference.

No redirect is followed and no `Retry-After` value causes a second send. The
credential reflection control uses the ordinary response-retention path. The
frozen R6-004 scanner checks token/header representations in seven encoded
forms, paths and bounded gzip contents. Publication and proof acceptance remain
separate predicates.

preparation component's request is retained as evaluator evidence and never
mounted in the HTTPS actor. Both request records must derive from the same
frozen prepared rows. Sanitized Lean context remains evaluator-only.

The canned response passes to the unchanged `provider_episode.consume`.
Its certificate envelope and completion-route receipt truthfully name that

name `canned_provider_response` as proposer. Future live attribution must be

suggest a newer component produced it.

The existing shared proof auditor is reused, with explicit additional
preparation/reconstruction context equality, exact expected declaration/type,
axiom policy, task/challenge identity, stage order and resource receipts.
D1 tests a local obligation within a larger downstream declaration. C8's
containing theorem remains a statement-identical `exact hlt` wrapper: it tests
local-proof binding and the large-coefficient path, not larger-context embedding.

## Reproduction and review

The native command requires the recorded toolchains, packages, runtime and
working user systemd/bubblewrap supervisor. Choose a fresh destination; the
runner refuses to overwrite an existing episode/checkpoint.

```bash
python3 -B experiments/r6/test_live.py \
  --run-dir experiments/r6/runs/https-reproduction-v1
```

Re-audit the existing complete checkpoint and its gate suite without a native
rerun:

```bash
python3 -B experiments/r6/reviews/2026-09-09/https_gates.py \
  --run-dir experiments/r6/runs/https-checkpoint-v1 \
  --gate-file experiments/r6/reviews/2026-09-09/R6-005-GATES.json \
  --output /tmp/r6-005-recount.json
```

The `--controls` flag additionally recreates the 15 disposable outer-gate
mutations. A fresh native run produces new canaries, TLS certificates and
timings, not the original episode bytes. This checkpoint was exercised in the
recorded checkout/runtime; cross-host relocation and a production network
entrypoint are not established by these local controls.
