# R6-007 — one authorized live call

Status: live result holds; harness **not closed**, 2026-09-13. **One provider
request, authorized by the author for one attempt, returned a Farkas witness
that the SDK verified, Lean consumed and the kernel replayed with empty axiom
deltas.** Priced ceiling of reported usage: 12,403 µUSD ($0.0124); not a bill.
The author's [independent review](reviews/2026-09-13/R6-007-REVIEW.md)
reproduced the certificate verification and both kernel replays byte for byte
and found six defects in the pilot's guards and in my first recount. This
report is corrected accordingly. The pilot is preserved as exploratory
evidence; its executing repairs go to a new policy, not to pilot-v1.

Historical audit: [pilot_audit.py](reviews/2026-09-13/pilot_audit.py) accepts
the six runs at 124 named cases
([R6-007-AUDIT.json](reviews/2026-09-13/R6-007-AUDIT.json)) and

## What the call was for

Seven checkpoints had exercised every boundary of the proposal interface with
canned responses and synthetic credentials and had made zero live calls. The
[preflight](R6-007-PREFLIGHT.md) — a dated pre-signing decision document,
retained as written, with its disabled-policy state and incomplete credential
instructions; not a runbook — argued that the next informative step was a
single real request through the frozen path: whether the IR-only proposal
interface yields anything a real model can answer usefully, not how often.

The pilot contract (`pilot_contract.py`, policy
[responses-live-pilot-v1](policies/responses-live-pilot-v1.json), lock
[pilot-harness-v1](policies/pilot-harness-v1.sha256.json)) binds the chain
`envelope → provider → credential → live → priced → priced_v2 → pilot` by
`previous_policy_sha256`, keeps the R6-006 v2 admission gate in host and actor,
and adds an author `authorization` record re-derived inside the actor, a
network stage mirroring `episode.stage` minus `--unshare-net`, and
`--mode live`, which refuses fixture inputs and requires the actor's CA digest
to match the pinned public bundle (`8c97794a…`, 121 certificates). Rehearsal
and live share one admission, one credential read, one TLS context and one
handoff.

Request parameters, unchanged from R6-006: `gpt-5.4-2026-03-05` requested and
allowed as the same dated ID, `reasoning.effort: medium`,
`max_output_tokens: 4096`, `service_tier: default`, `store: false`, one attempt,
no automatic retry. The signed policy carries `campaign_attempts: 1` and
`total_micro_usd: 102400`. The "signature" is a name/timestamp record in a
canonical policy file, not a cryptographic signature.

## The witness

The model returned one message whose text is exactly the JSON the prompt asked
for, echoing the request digest `e449c34f…` and proposing

```
1 · hwidth  +  32769 · neg_goal
```

Recomputed from the retained request rows: `hwidth` is
`−18446744069397807104 + 65538·Zmax ≤ 0` and `neg_goal` is
`18446744069397807106 − 2·Zmax ≤ 0`; the weighted sum cancels `Zmax`
(65,538 − 2·32,769 = 0) and leaves the constant 604,462,909,666,027,343,249,410,
which is positive. The SDK's verdict is `verified_farkas`
(`sha256:a5c6b577…`); the review re-ran the verifier and both kernel replays
and reproduced the raw reports byte for byte.

What this witness is, stated carefully. Every successful **D1** witness the
harness had handled before — the deterministic goldens and the R6-001 through
R6-006 canned fixtures — combined `hZ` (`Zmax ≤ 65536`) with `neg_goal`,
sometimes adding `hnum`. (The C8 controls use `hhi` and are not comparable.)
This one uses `hwidth` with multiplier 32,769 and does not touch `hZ`. That
places it outside D1's bounded enumeration, whose coefficient bound is 3. It
does **not** place it outside the deterministic recovery mechanism: the
review's [exact-recovery diagnostic](reviews/2026-09-13/R6-007-REVIEW-EXACT.json)
shows the existing SDK exact recovery, given the same IR restricted to the
`hwidth` hypothesis, produces exactly `hwidth + 32769·neg_goal`. On the full
IR both bounded search and exact recovery return `2·hZ + neg_goal` first. So:
a different observed support from the deterministic first hit, outside bounded
enumeration, inside the deterministic mechanism's witness space. No capability
claim follows from one sample.

The proof export is `862f16b9…`. Rehearsal-4's canned witness reproduces
R6-003's canned-path D1 export `cd6081da…`; the three golden deterministic
broker episodes export `f4c179f3…`. Three different proofs of the same
obligation, accepted by the same kernel.

## Defects, and where they go

Nothing below is repaired in place. Pilot-v1 stays frozen as the record of
live-2; every executing fix belongs to a new policy exercised by controlled
runs before another provider call. The historical auditor covers the retained
artifacts as they are.

**P1 — The one-attempt cap is per run directory, not per authorization.**
`pilot_episode.invoke` opens `run/'reservation-ledger.ndjson'`, so every new
`--run-dir` starts a fresh budget, and `pilot_budget.reserve` checks only that
file. live-1 and live-2 each reserved 102,400 µUSD under the same signed
policy: 204,800 reserved against a 102,400 ceiling. The review's offline probe
opens two further ledgers under the same policy and both host and actor admit
both; only a second row in the *same* ledger is refused. The
`ledger_ceiling_is_one_attempt` control checks policy numbers and never calls
the ledger. My earlier statement that another call "needs a new signature" was
an operator rule, not an executing guard. The actor's `live_authorization`
also accepts `maximum_micro_usd: 0` and an empty `approved_by` that the host
check rejects. live-1 made zero connections, so this is one transmission, not
two charges — the auditor pins `transmissions_started: {live-1: 0, live-2: 1}`
and records the reservation over-commitment rather than hiding it. New policy:
an authorization-scoped ledger outside run directories, atomic reservation,
explicit treatment of pre-send failures, and the full authorization scope
enforced identically in host and actor.

**P1 — My first recount was not an auditor.**
[pilot_final_checks.py](reviews/2026-09-13/pilot_final_checks.py) read
selected claims. The review mutated twelve relationships — wrong task, wrong
target type, `sorryAx`, invalid proof export, reconstruction target `False`,
substituted certificate coefficient, `accepted: false` host admission, a `{}`
ledger, altered outbound bytes, a corrupted rehearsal-4 proof, a changed live-1
file, an extra `live-3` directory — and all twelve still passed its 230
predicates, 167 of which were per-event hash checks. That file is retained as
history and superseded. [pilot_audit.py](reviews/2026-09-13/pilot_audit.py)
reconstructs the relationships from retained bytes: each run's policy, lock and
sources from its own provenance; requests and arguments regenerated through the
frozen builder against the retained policy; host and actor admission
re-derived; ledger rows against permit, reservation and bindings; the actor's
transport record against the serialized and captured bodies; interpretation
reproduced; accounting recomputed; the shared R6-002 proof checker with task,
context and witness equality; the expected event sequence per run; the exact
six-run population; live-1 against a retained
[193-file inventory](reviews/2026-09-13/R6-007-LIVE1-INVENTORY.json) (191
Git-selected; `--retained-only` for a clean checkout); the operator scan's
inventory bound to the audited bytes. Cases are a fixed named population of
124, asserted exactly, not counted. The controls reject all twelve review
mutations plus eleven more (dropped duplicate receipt, provider status 500,
second ledger row, retrofitted attribution, file added after the scan, altered
retained policy, changed rehearsal source under an unchanged lock, zeroed
challenge digest, failed process record under agreeing receipts, and a
rejected scan status in either the summary or the full report) at the intended
case, and accept the unmutated copy in both scan routes and a retained-only
copy. Mutations are audited through the summary-only scan route, so the
operator inventory cannot mask a missing semantic comparison — the review's
second pass showed it had been doing exactly that for three of the four
auditor gaps.

**P2 — Live mode discarded a locally available transport check.**
`pilot_budget.interpret` requires both `sent` and `received` captures before
comparing either to the serialized body; with no local receiver, `accepted` is
always `null`, and altered outbound bytes pass production interpretation. The
auditor splits the predicate: `serialized == outbound` is checked, remote
receipt is recorded as unobservable. Authentic live-2 has equal local bytes.
New policy: the same split in the executing path.

**P2 — The live trace misattributes the proposer and duplicates receipts.**
The verdict and `recovery_started` name `live_model_response`;
`certificate_assembled` and `recovery_finished` name `canned_provider_response`
with route `openai_responses_http_fixture_v1`, hardcoded in the reused R6-003
consumer. Events 13/14 and 15/16 are two `stage_started` and two
`stage_finished` receipts for one `proposal-1` process, because
`pilot_network.stage` appends receipts the frozen supervisor already appends.
The auditor pins the literal values and the interpretation: the pair of finish
payloads must agree, and any retrofitted attribution is rejected. My earlier
"new proposer identity" claim described the verdict, not the whole trace. New
policy: proposer provenance passed through the consumer; the supervisor owns
stage receipts.

**P2 — Credential use, exact receipt and publication evidence are separate.**
`exact_receipt` is set for any non-401 status. The auditor records the
narrower meaning. The live-mode publication scan is vacuous: `invoke` sets
`canary = None` in live mode and `finalize` still scans for the synthetic
canary, which was never mounted. The operator scan closes the gap for these
bytes — the author ran
[operator_disclosure_scan.py](reviews/2026-09-13/operator_disclosure_scan.py)
over `experiments/r6`: the frozen `publication.scan` with the operator's token
as canary, both representations, all seven encoded forms, 43,108 files and 349
gzip streams, zero disclosures, nothing unreadable or incomplete; the
[summary](reviews/2026-09-13/operator-disclosure-scan.summary.json) binds the
full report by digest `64ded869…`, and the auditor binds the scanned
`pilot-runs` digests to the audited bytes. Its limits: there is no retained
commitment to the header actually sent, so the identity of the scanned value
with the transmitted value is an operator assertion; and files added after the
scan — this report, the review, the audit records — are outside it. New
policy: a commitment recorded at the credential handoff, a scanner receipt
bound to it and to the final publication inventory, and the operator-mediated
full-value scan kept until a digest-matched candidate search establishes
equivalent coverage.

**Smaller.** A credential-format failure is a traceback, not a record: the
credential read sits outside the actor's `try`, so live-1's `http.json` is the
all-null initial record and its only evidence is stderr (`credential_format`,
no header text). `StageFailure` prevents finalization for every failed live
stage, not only this one — live-1 is unsealed, and timeouts, resource failures
and later proof stages would be too. `live_model_calls` derives from
`body_sends_returned`, so a partial send with unknown provider processing would
report zero calls; the auditor retains `transmissions_started` and
`transmissions_returned` separately. `live_model_cost_usd` is a usage-priced
estimate and must not become a billing observation downstream. The R6-004
actor classified the format case; the pilot regressed it.

## Scope

One sample, one obligation, and an obligation whose deterministic proof was
already in hand. The call establishes that the IR-only proposal interface,
through every boundary the seven checkpoints built, produces something a real
model answers with a usable certificate. It establishes nothing about rate,
robustness, other obligations, or any advantage over deterministic recovery.
Cohort selection is the separate next piece of work, after the guards above are
repaired under a new policy.

presupposes an unsigned policy and its last direct run (12:54 UTC+2) predates

frozen sources with the three signature fields viewed as unsigned; the
substitution is recorded in the output. The rehearsals reproduce with
`pilot_episode.py --mode rehearsal`; the live attempt does not, and — see P1 —
the harness itself would not stop a second one.
